# INCREMENTS — Signal Doctrine

**Version:** May 2026  
**Status:** Canonical

Data philosophy for INCREMENTS — what counts as signal, when it surfaces, when the product stays silent.

---

## Definition

**Signal** = specific, observable, mechanism-linked information that changes the operator’s next decision.

**Noise** = vanity metrics, ambiguous pseudo-signal, engagement theater, or interpretation without evidence window.

---

## Evidence hierarchy (highest → lowest)

1. **Observed repeated behavior** — completions, timestamps, shift logs, ledger entries  
2. **Recent longitudinal patterns** — 7–14 day windows for Wendy  
3. **Explicit operator declarations** — energy state, debrief fields  
4. **Static psych frameworks** — hypotheses, not verdicts  
5. **Generic behavioral assumptions** — lowest; often wrong for this operator  

Declared identity does not override telemetry.

---

## When signal surfaces

| Condition | Surface? |
|-----------|----------|
| Traceable input exists for this moment | Yes — one line max on execute; more on interpret surfaces |
| Pattern meets Wendy gate (specific, falsifiable, cooldown) | Yes — Brief only |
| Trait computed from ≥N days usage | Yes — Intel, collapsed default |
| Generic encouragement would fill slot | **No** |
| Low confidence emerging mechanism | **No** or tentative wording |
| Post-session / post-log with earned data | Direct observation allowed |

**Silence doctrine:** silence is correct when confidence is low or observation is generic.

---

## When signal is hidden

- No log → no fake trend  
- Insufficient days → “Collecting” not fabricated insight  
- Deferred cards (ObservedIntelligence on Today) — engine may run; UI empty until stable  

Hiding is not failure — it protects trust.

---

## Signal vs verdict language

| Verdict (avoid) | Signal (use) |
|-----------------|--------------|
| DOMINANT FRICTION: Sequencing | OBSERVED PATTERN: Repeated sequencing stalls (14d) |
| You are displacing creative work | Admin active. Creative work has not started. |
| Participation failure | Participation’s been quiet. Worth touching today. |

Wendy payload: signals inform reasoning — they are not sentences that replace operator judgment.

## Domain signals (examples)

### Hideout

- 30-day average gross, repeat %, band classification  
- Shift log row — actuals, not targets  
- Friction audit checkboxes — physical discovery truth  
- Friday signal log — weekly seed review  
- Experiment sprint checkboxes — hypothesis in flight  

**Not signal:** imaginary throughput “customers per day” without data; motivational band names without dollars.

### Distribution (Signal tab)

- Monday block completion, ledger confirmation  
- Week record in `DistributionWeek`  
- Venture-specific capture banners (Tue/Sat FORM)  

**Not signal:** rep-counter validation UI; streak of “distribution days.”

### Operator (Intel)

- Avg first action hour, morning execution %, completion clustering  
- Admin displacement days count  
- Dominant high-friction system from action tags  

**Not signal:** personality type labels as destiny; Dossier-style self-help framing.

---

## Interpretation rules

1. **Interpretation improves action** — if a line doesn’t change the next move, cut it  
2. **Intelligence reduces friction** — never adds a second coaching voice on execute  
3. **Mechanism when adherence matters** — science-linked protocol notes (see Master Explanation Doctrine)  
4. **Anti-dependency** — observations must not create appetite for more observations  

---

## FORM / Forge cross-venture

Distribution OS and venture gates live in BRICE_OS docs. INCREMENTS **displays state** — does not rewrite Forge programming doctrine.

Forge gate cleared = boolean signal for Ventures row — not hype copy.

---

## Anti-patterns

- AI summary of your week without cited inputs  
- Streak counters as health of system  
- Aggregate operator score hero  
- Narrating obvious state (“You have 3 tabs open”)  
- Filling Intel traits slot with static copy  
- Predicting psychology (“you’re avoiding grief”)
